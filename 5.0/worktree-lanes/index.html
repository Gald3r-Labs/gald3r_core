    Worktree lanes — human chat, implementers, and reviewers¶

    How this factory keeps coding, review, and your interactive chats from colliding on the same working tree. No new product: same git repo, same main, different directories.

    The three seats¶

    Seat Directory What happens here
    Primary (orchestration) The folder git calls the main worktree — today gald3r_core_exp Housekeep, merge, gald3r worktree create/remove, review-result commits, board verbs (gald3r task / bug). Prefer this tree clean while a wave is in flight.
    Implementer lane A gald3r-owned worktree under .gald3r-worktrees/<repo>/ Code, tests, CHANGELOG for one task/bug. Commit on that branch. Do not hand-edit the live board here — use gald3r … --dir <primary>.
    Reviewer lane A review-swarm worktree Reads a SHA, writes a verdict. Does not need your chat dirt.
    Human / interactive chat A long-lived human worktree or Throne / gald3r project-agent / Valkyrie Your questions and WIP. If Cursor is pointed at primary, every overlay edit is mixed-dirty for the next housekeep.

    The project agent (T1167) is the intended human seat: you talk to the project; it uses board verbs on primary; coding agents stay in lanes.

    What "clean primary" actually means¶

    A reviewer already looks at a commit (the worktree SHA). The whole machine does not need to be clean. Primary must be clean enough for housekeep, spawn, and merge. Human or chat dirt on primary is the mixed-dirty stop.

    Implementer dirt inside a lane worktree is allowed.

    Daily pattern¶

    1. Leave primary for orchestration. Do not park overlay WIP there while reviewers run.
    2. Do factory coding in a lane (gald3r worktree create --task-id N --role agent).
    3. Land lane work by committing in the lane, then merge to primary when housekeep is idle — same as an agent bucket.
    4. When you must touch primary (board verbs, cut, merge fight): do that, housekeep if you dirtied .gald3r/, and stop. Do not leave .cursor / .claude WIP sitting there.
    5. Talk to the project with gald3r project-agent / @g-project-agent or Throne, not by treating primary as a scratch tree.

    Why .gald3r/ still shows up in lanes¶

    Git worktrees check out tracked files. gald3r.db is already gitignored. Lane sparse-checkout hides tasks/ and bugs/ (BUG-1404) so a stale board snapshot cannot be rescue-committed onto main. Other .gald3r/ files may still materialize. Lanes read/write the board only via --dir <primary>.

    Gitignoring the live board is correct for a consumer SDLC project (local DB, or later world_tree). This factory / any WPAC controller still commits .gald3r/ until world_tree is the shared store. That is T867 unfinished conversion, not a second design.

    What not to revive¶

    Environment branches named dev / test / live model promotion, not working-directory contention. They do not fix mixed-dirty and they re-open 3-way merges on the board and overlays.
